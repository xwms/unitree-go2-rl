# 阶段 2：验收与交付

目的：记录二阶段（直梯 / L 梯 / 螺旋楼梯的攀爬与下行）的验收结果、交付物归档方式和部署导出流程。本文对应代码状态 commit `315d343`。

## 1. 验收结果

评估协议（`src/go2_stair/go2_stair/scripts/eval_stair.py`，按论文 Sec. 6 实现）：

- 固定台阶高度、无课程、无目标终止；成功 = 到达目标位姿（xy 0.35 m / z 0.12 m / 航向 0.45 rad），抵达瞬间冻结统计。
- 每个高度 300 局（每种地形 100 局）。
- 每个高度单独起一个进程（同一进程内创建第二个仿真环境会挂起）。

结果（19300→20300 续训 run 的最终 checkpoint，2026-11-26 评估）：

| 台阶高度 | 直梯 | L 梯 | 螺旋 | 聚合 |
|---|---|---|---|---|
| 0.04 m | — | — | — | 94.7% |
| 0.06 m | — | — | — | 93.3% |
| 0.08 m | 93% | 82% | 91% | 88.7% |
| 0.10 m | 92% | 93% | 76% | 87.0% |
| 0.12 m | 95% | 88% | 79% | 87.3% |
| 0.14 m（OOD） | — | — | — | 88.3% |

验收线：聚合 ≥ 80% ✓；直梯 ≥ 90% ✓；L 梯 ≥ 80% ✓；螺旋 ≥ 70% ✓；0.14 m 分布外 ≥ 60% ✓。

训练侧终态读数：

- goal_reached ≈ 95%，time_out ≈ 0，bad_orientation ≈ 4–6%（回合加权）；
- 平均回合长度 ~125 步（约 2.5 s 快速爬完整梯）；
- `Curriculum/terrain_levels` 在 6.5–7.6 之间平衡震荡（升一降一），低于真实能力——以 eval 为准，0.12–0.14 m 均保持 87–88%。

判读注意：

- mean_reward 不是进度指标：快速胜利经济下约 10–20；历史上悬停刷分时期曾达 40–65，数值不可跨设计比较。
- eval 的 mean_lin_vel / mean_power 在部分行偶发为 0（记账时序问题），不影响成功率。

## 2. 交付物归档

统一归档到 `logs/rsl_rl/go2_stair_stage2/deliverable_stair.pt`：

```bash
RUN="$(basename "$(ls -dt logs/rsl_rl/go2_stair_stage2/2026-*/ | head -1)")"
CKPT="$(ls "logs/rsl_rl/go2_stair_stage2/$RUN"/model_*.pt | sort -V | tail -1)"
cp "$CKPT" logs/rsl_rl/go2_stair_stage2/deliverable_stair.pt
```

交付清单：

| 交付物 | 位置 | 说明 |

| 策略权重 | `logs/rsl_rl/go2_stair_stage2/deliverable_stair.pt` | rsl-rl checkpoint（actor + critic + optimizer） |

## 3. 部署导出步骤

前置：仓库同步至 commit `315d343`。

1. 导出 JIT / ONNX（专用导出脚本；isaaclab_rl 自带的 ONNX exporter 假设 actor 是
   `nn.Sequential`，不适用于自定义的 `HeightmapActorCritic`）：

```bash
bash scripts/train_stair.sh export \
  --checkpoint logs/rsl_rl/go2_stair_stage2/deliverable_stair.pt
```

产物写入 checkpoint 同级目录 `exported/policy.pt` 与 `exported/policy.onnx`（含观测归一化层），
并自动打印 JIT 与 ONNX 在随机观测上的最大输出差（需安装 onnxruntime，正常应 < 1e-4）。

2. 集成口径（部署端需要知道的三件事）：

- 观测：**522 维** = 45 本体 + 4 目标位姿相对量 (dx, dy, dz) + 航向误差 + 32 足高 + 441 高度图（21×21，行主序，位于末尾）；
- 控制：**50 Hz**（`step_dt = 0.02 s`），动作为 12 维关节位置目标，scale/offset/clip 见 deploy.yaml；
- 目标指令：把"目标位姿相对量 + 航向误差"按 deploy.yaml 中 `observations.goal` 的 scale 填入第 46–49 维。

3. 导出后校验：

- ONNX 输入 shape `(1, 522)`、输出 `(1, 12)`；
- 在 Isaac 中采集一条观测，对比 ONNX 输出与训练策略输出（误差 < 1e-4）；
- `bash scripts/test_mujoco.sh --headless` 确认 MuJoCo 场景可加载（现有脚本仅做模型冒烟测试，策略回放需另行接入）。

## 4. 已知遗留（不阻塞交付）

- eval 的 mean_lin_vel / mean_power 记账偶发为 0：`finish_episodes` 的累积时序问题，不影响成功率；
- `Episode_Reward/topped` 触发率偏低（~0.02–0.04）：goal 奖励是主项，不影响训练；
- 课程前沿（6.5–7.6）低于真实能力（0.12–0.14 m）：若继续训练，可放慢课程节奏（连续两次成功才升级）来缩小差距。

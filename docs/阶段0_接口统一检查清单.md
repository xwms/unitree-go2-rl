# 阶段 0：接口统一检查清单

目的：在训练行走/跳跃模型之前，把三个运动任务（楼梯、行走、跳跃）的观测、动作、网络、环境骨架固定成同一套接口。接口不一致会导致 warm start 作废、部署代码要写三份。**任何新任务需要的额外信息，只能塞进 4 维任务指令槽或编码进高度图**，不得改动 522/12 布局。

## 1. 观测接口（固定 522 维）

- [ ] 观测组名固定为 `policy`，`concatenate_terms = True`，总维度 **522**
- [ ] 布局固定：`45 本体 + 4 任务指令槽 + 32 脚高 + 441 高度图`
- [ ] 本体 45 维：base_lin_vel(3) + base_ang_vel(3) + projected_gravity(3) + joint_pos(12) + joint_vel(12) + last_action(12)，顺序固定
- [ ] 任务指令槽固定 **4 维**，各任务含义：
  - 楼梯：目标位姿相对量 (dx, dy, dz) + 航向误差
  - 行走：(vx, vy, wz, 0)
  - 跳跃：(vx, vy, 障碍触发/距离, 0)
- [ ] 脚高 32 维：4 个脚部扫描器 × 8 射线，顺序固定（FL/FR/RL/RR）
- [ ] 高度图 441 维：21×21 扫描器，行主序，位于观测末尾（CNN 依赖这个位置）
- [ ] 各观测项的 scale/clip/noise 配置三个任务保持一致（噪声幅度可按任务微调，但维度与顺序不可变）
- [ ] height_scanner 配置固定：21×21 射线、量程、安装位姿、`update_period = decimation × dt`
- [ ] 4 个脚部扫描器命名与 Go2 足端绑定固定

参考实现：`src/go2_stair/go2_stair/tasks/locomotion/robots/go2/stair_env_cfg.py`（PolicyCfg）、`mdp/stair_observations.py`

## 2. 动作接口（固定 12 维）

- [ ] 动作项固定为 `JointPositionActionCfg`，12 个关节、**名称与顺序固定**（与 Go2 默认姿态一致）
- [ ] `scale` / `offset` / `clip` 三个任务一致
- [ ] 机器人驱动 PD 参数（stiffness / damping / effort limit）一致，不改 `robot cfg`
- [ ] 控制频率固定：`decimation = 4`、`sim.dt = 0.005` → **50 Hz**
- [ ] 动作维度检查：`env.action_space.shape == (12,)`（单环境）

## 3. 网络接口（warm start 的前提）

- [ ] 三个任务共用同一个网络类 `HeightmapActorCritic`（`agents/heightmap_net.py`），参数固定：
  - 输入 522，`PROPRIO_DIM = 81`，`HEIGHTMAP_SIZE = 441`，`CNN_OUT_DIM = 128`
  - CNN：1→8→16→32 通道，2×2 maxpool ×2，avgpool 3×3/stride2（等价 adaptive 2×2，ONNX 可导出），flatten
  - MLP 隐藏层 `[128, 128, 64]`，ELU
- [ ] `obs_groups = {"policy": ["policy"], "critic": ["policy"]}`
- [ ] `noise_std_type = "scalar"`，`init_noise_std = 1.0`
- [ ] 检查方式：三个任务的网络实例化后 `state_dict` 的**键名与形状完全一致**（见第 8 节命令）

## 4. 环境骨架

- [ ] 同一个 Go2 资产（`stack/unitree_model/Go2`）与默认关节角
- [ ] 传感器集合固定：contact_forces（`history_length=3`、`track_air_time=True`）、height_scanner、4 个脚部扫描器
- [ ] `episode_length_s = 20.0`，`sim.dt = 0.005`，PhysX 设置（`gpu_max_rigid_patch_count` 等）一致
- [ ] 地形生成框架统一用 `StairTerrainGeneratorCfg`（不同任务只换 `sub_terrains` / 难度范围）
- [ ] 重置逻辑结构一致（reset 事件签名与姿态随机化机制相同，参数范围可按任务调整）

## 5. 任务间允许的差异（仅此四处）

| 项 | 楼梯 | 行走 | 跳跃 |
|---|---|---|---|
| **命令项** | 目标位姿 | 速度指令 | 速度+障碍触发 |
| **奖励** | 导航+路径+正则 | 速度跟踪+正则 | 前进+腾空+落地+正则 |
| **地形** | 金字塔/直梯等 | 平地/粗糙 + 混 20~30% 楼梯 | 障碍课程 + 混行走/楼梯 |
| **终止** | 到达/超时/跌倒 | 超时/跌倒 | 超时/跌倒/越障完成 |

其余（观测、动作、网络、传感器、频率、episode 长度）一律不得改动。

## 6. 注册与命名

- [ ] 每个任务一个 gym id：`Unitree-Go2-Stair-Stage1/Stage2`、`Unitree-Go2-Walk`、`Unitree-Go2-Jump`
- [ ] 每个任务一个 `experiment_name`（`go2_stair_stage1/2`、`go2_walk`、`go2_jump`），日志互不覆盖
- [ ] 每个任务一个 PPO runner cfg，**除 experiment_name 外其余超参一致**（网络、batch、学习率、entropy_coef=0.003）
- [ ] 注册桥 `scripts/register_bridge.py` 增加新任务的 `gym.register` 条目，部署后 `list_envs.py` 全部可见

## 7. 训练配置基线

- [ ] `num_envs = 8192`（RTX PRO 6000 甜点）
- [ ] `num_steps_per_env = 24`、`save_interval = 100`、`max_iterations` 按任务定
- [ ] 断点续训机制验证：`--resume --load_run <绝对路径> --checkpoint model_X.pt` 可用（跨任务 warm start 依赖它）

## 8. 验收检查项

- [ ] 三个任务的观测形状打印均为 `(num_envs, 522)`
- [ ] 三个任务的动作形状均为 `(num_envs, 12)`
- [ ] 三个任务网络 `state_dict` 键名/形状完全一致
- [ ] **warm start 冒烟测试**：行走任务 resume 楼梯 checkpoint 能正常启动并跑完 10 轮
- [ ] 每个任务的 eval 协议可运行（复用/扩展 `scripts/eval_stair.py`）
- [ ] 旧任务回归评估脚本就绪（新模型训完后验证旧能力不退化）
